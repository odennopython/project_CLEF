# 試作 0.1「返し」の計画

[11-kaeshi-system.md](11-kaeshi-system.md) の戦闘システムを、触って確かめられる最小の形にする。

## 1. 目的

紙の上では判断できない、次の4つの仮説を確かめる。

| # | 仮説 | 確かめ方 |
|---|---|---|
| 1 | 指が触れた瞬間でタイミングを判定し、はじいた方向で向きを決める操作が気持ちいい | オーナーがiPhoneで遊んだ感想 |
| 2 | 三つの先（後の先・対の先・先の先）の違いが、手応えではっきりわかる | 同上。記録パネルで判定の内訳も見られるようにする |
| 3 | 物理に従う予備動作は、初めて見る攻撃でも読める | 説明しない法則（返す向き、虚の見分け方）に、遊びながら気づけるか |
| 4 | ゲージなしで、体の様子だけで崩れが読める | 体勢を数字やゲージで見せずに、勝ち負けの流れがわかるか |

**作らないもの**：探索、移動、複数の敵、成長要素、メニュー。敵1体との一騎打ちだけ。

## 2. 面白さのための設計判断

### 2-1. 「本物の起こり」と「虚」を物理で見分けられるようにする

- 本物の攻撃は、**腰から動き出す**。重心が移り、足が雪を擦る音がして、足元の影が動く。そのあと腕と刀がついてくる。
- 虚（フェイント）は、**腕と刀だけが動き、腰と影は動かない**。足の音もしない。
- この法則は説明しない。気づいた人だけが、虚を見切って先の先を取れる（仮説3）。
- 足元の影は、腰の真下に落ちる。重心の移動が、影の動きとして一目でわかる。

### 2-2. 重さが時間を決める

- すべての攻撃に「重さ」がある。重いほど、起こりと振りかぶりが長く、返したときの崩しも大きい。
- 重い攻撃は先の先を取りやすいが、外すと痛い。軽い連撃は速いが、崩しは小さい。
- 起こりの長さ＝150＋150×重さ（ミリ秒）。振りかぶり＝220＋330×重さ。振り下ろし＝110＋70×重さ。

### 2-3. 返す向きの法則：刃の流れに沿って流す

- 刀は、振りかぶった方向の逆へ流れる。その流れに沿ってはじくと、相手は自分の勢いで体勢を崩す（合気の考え方）。
- 流れに逆らってはじくと、受け止めることになり、崩しは小さく、自分も少し押される。
- 突きは、左右どちらかにはじけば流せる。
- この法則も説明しない（仮説3）。

### 2-4. 段階ごとに、戦いの主導権が変わる

| 段階 | 敵の連撃への影響 | 崩し（重さ1の攻撃、流した場合） | 手応え |
|---|---|---|---|
| 後の先 | 連撃は続く | 10 | 短い停止、小さな火花、澄んだ高い音 |
| 対の先 | 流せば連撃が止まる | 22 | 長めの停止、大きな火花、画面が一瞬明るくなる |
| 先の先 | 攻撃そのものを断つ | 34 | 時間がゆっくりになる、最も高く長く響く音 |

上の段階ほど、戦いの拍子を自分のものにできる。

### 2-5. 状態は「白い息」で見せる

- オーナーの情景「真夜中に白い息を吐く」を、体勢の表現に使う。
- 体勢が崩れかけるほど、**息が荒く、速く、大きく白くなる**。構えが沈み、刀先が震える。
- 敵も自分も同じ。ゲージは出さない（仮説4）。

### 2-6. 拍子

- 敵は呼吸の拍子に合わせて攻撃を始める。拍子を読めれば、起こりを予測できる。
- 後半は、拍子を外す「溜め」（振りかぶったまま止まる）と、虚が混ざる。

### 2-7. 一閃と残心

- 敵の体勢が崩れきると、膝をつく。そこで一度はじけば、一閃で決着する。
- 一閃の瞬間は、時間が止まり、音が消え、白い線が走る。そのあと、雪の音だけが残る。
- 敵は2回崩す必要がある（前半・後半）。後半は虚と溜めと軽い連撃が加わる。負けたら、その段階からすぐにやり直せる。

### 2-8. 人間工学

- 縦持ち・片手。画面の上側に敵、下側に親指。画面のどこをはじいてもよい。
- タイミングは指が触れた瞬間で判定。方向は、その後の指の動き（14ピクセル以上）で判定。動かさずに離した場合は「方向なし」。
- 判定の時間は、読めば間に合う長さを基準にする：対の先は前後80ミリ秒、後の先はその手前145ミリ秒。
- 入力と表示の遅れを補正する。初期値25ミリ秒、成功した弾きのタイミングから自動で調整する。
- PCでは、マウスでドラッグするか、矢印キー（方向）とスペースキー（方向なし）で遊べる。

| 項目 | 内容 |

| 置き場所 | `prototype/kaeshi/index.html` |
| 見た目 | 雪の夜。月明かりの冷たい光と、遠くの灯籠の温かい光（寒さと温かさの対比）。人物は単純な形の組み合わせで、動きは手続き的に作る（素材の制作なし） |

| 試験用の仕組み | `window.__kaeshi` に、状態の取得、速度の変更、自動で弾く機能を用意する。自動試験で、勝利までの流れが壊れていないかを確かめる |

## 4. 検証の手順

1. ブラウザ（Chromium）で開き、エラーが出ないことを確かめる。
2. 自動で弾く機能を使って、前半と後半を崩し、一閃で勝つまでの流れが最後まで動くことを確かめる。
3. 何もしない場合に、負けて、やり直しができることを確かめる。
4. 縦長（iPhone相当）と横長（PC相当）の画面で表示を確かめる。
5. 公開して、オーナーにiPhoneで遊んでもらい、仮説1〜4の感想をもらう。

## 5. 0.1で割り切っていること

- 振動は入れない（iPhoneのブラウザは振動に対応していない。Godot版で入れる）。
- 人物の動きは単純な形の組み合わせ。手触りの検証には十分だが、本番の見た目ではない。
- 敵は1体、攻撃は5種類（右薙ぎ、左薙ぎ、振り下ろし、斬り上げ、突き）と、虚、溜め。

### 自動試験（Chromium、縦長 390×844 と横長 1280×720）

| 試験 | 結果 |
|---|---|
| 読み込み | エラーなし。ソフトウェア描画でも毎秒約50フレーム |
| 自動で弾く（等速、対の先だけ） | 25秒で対の先9回、被弾0、空振り0 |

### 試作中に直したこと

- 最初の構図では、自分の体が相手を隠していた。相手の腰と影は「本物の起こり」を見分ける手がかりなので、カメラを右肩の後ろに上げ、自分を左下に置いた。
- 雪の地面が明るすぎて夜に見えなかったため、暗くした。
- 腰の動きを読みやすくするため、相手と自分の腰に明るい帯を付けた。

# 試作 0.2 の計画（オーナーの評価を受けて）

## オーナーの評価（2026-10-29）

> よいが動きが少ないよね。相対的な動きがないから緊張感が出ないし、全体的な動きも少ない。駆け引きも少ないから、はらはら感もない。自分も相手もオブジェクトが単調すぎて面白くない。魅せがないよね。

## 原因

| 指摘 | 原因 |
|---|---|
| 相対的な動きがない | 二人とも定位置に立っている。間合い（距離）が一度も変わらない。緊張の多くは、間合いが変わることから生まれる |
| 駆け引きがない | 弾く以外の選択肢がない。攻める、退く、回り込む、誘う、が一つもない。待って反応するだけになっている |
| はらはら感がない | 危険は攻撃が届く瞬間にしかない。その前に緊張が積み上がる仕組みがない |
| 単調なオブジェクト | 関節がなく、布や足の動き（二次的な動き）がない。何も反応しない |
| 魅せがない | 毎回同じ手応え。連続しても何も高まらない。カメラが動かない。大きな瞬間の演出がない |

## 0.2 の設計

### 1. 間合い（相対的な動き）

- 二人とも雪の上を動く。相手は間合いを測りながら回り込み、詰め、離れる。
- 攻撃には届く距離がある。相手は踏み込みながら斬る。遠い間合いからは、雪を蹴って一気に詰める突進攻撃がある。
- カメラは自分の背中の後ろから相手を見続ける。回り込むと世界が回り、灯籠や木々が流れる。

### 2. 駆け引き（はじく向きの意味を、状況で変える）

操作は「はじく」1つのまま。相手の攻撃の判定の時間内なら返し、それ以外では体の動きになる。

| はじく向き | 相手の攻撃の判定内 | それ以外 |
|---|---|---|
| 上（相手の方へ） | 返し | **踏み込み斬り**（攻める） |
| 下 | 返し | **退く**（短い無敵時間） |
| 左右 | 返し | **回り込む**（短い無敵時間） |

- 相手には**隙**がある（攻撃を出し切った後）。そこに踏み込めば斬れる。隙でないときに斬りかかると、相手に受けられて反撃される。
- 後半、相手は**誘い**（わざと隙を見せる）を使う。本物の隙は腰が伸びて力が抜け、誘いは腰が沈んで溜まっている。0.1の「腰の法則」と同じ法則で見分けられる。
- **危険な技**（返せない技）がある。刀が赤く光る。低い薙ぎ払いは退いて避け、危険な突きは回り込んで避ける。返すか避けるかの判断が加わる。
- **相手が自分を学ぶ**。早押しが多いと虚と溜めを増やし、斬りかかりが多いと誘いを増やし、退きが多いと突進で追ってくる。

### 3. 緊張の積み上げ

- 相手が間合いに入ってくること自体が脅威になる。
- 剣戟の連続：返すたびに音の高さが音階で上がっていく。被弾や空振りで元に戻る。連続が続くほど、手に汗を握る。

### 4. 生きた体

- 膝と肘を持つ手足（二関節の逆運動学）。
- 足は雪の上に置かれ、体が動くと一歩ずつ踏み出す。雪に足跡が残り、踏むたびに雪が舞う。
- 袴の形。相手には笠と、ぼろぼろの外套の布。自分には長い赤い襟巻き。布は動きに遅れてなびく。

### 5. 魅せ

- 打ち合った瞬間に、その場所が光って周りを照らす。地面に衝撃の輪が広がる。
- 先の先や対の先では、カメラが一瞬寄る。
- 一閃では、カメラが横に回り込み、時間がゆっくりになる。
- 後半に入ると、大きな「弐」の字が浮かび、相手の刀がかすかに赤みを帯びる。

# 試作 0.3：人物の形と動き

## オーナーの評価（2026-10-29）

> 人がカクカクすぎて話にならない。ちゃんと人体がデフォルメされていても、カッコよく動くべき。

## 原因

| 層 | 原因 |
|---|---|
| 形 | 円柱と箱の組み合わせで、関節の継ぎ目がすべて見えていた。人ではなくロボットに見えた |
| 動き | 姿勢から姿勢へ、手の位置を直線で補間していた。人の動きは弧を描き、腰が先に動いて腕と刀が後から追い、止まるときは行き過ぎて戻る。そのどれもなかった |

## 0.3 で変えたこと

### 形
- 墨の輪郭線（背面を少し大きく描く方法）と、三段階の影（トゥーン）。単純な形でも、意図したデフォルメに見える。
- 腰は細く胸と肩は広い胴（回転体）。肩と肘は球で継ぎ目を隠す。
- 袴は腰から足首への広がった筒で、膝を隠す。広い袖は重さで垂れ、腕の動きに遅れてついてくる。
- 反りのある刀身、鍔、柄。
- 相手は笠と、ぼろぼろの外套。自分は髷と、赤い襟巻き。
- 色の変換を直した（指定した色が明るく薄く出ていた）。

### 動き
- 手と刀は、直線ではなく肩の前の支点を中心に**弧**を描く。
- 振りは**腰と胴が先**に回り、腕と刀が後から追いつく（運動連鎖）。振り抜いた後も胴が回り続ける。
- すべての関節を**ばね（二次の動き）**に通す。刀はしなり、止まると行き過ぎて戻る。振りの最中だけばねを硬くし、刃が届く瞬間の判定とずれないようにした。
- 動く向きに体が傾く。首は相手の方を向く。胸が呼吸でわずかに膨らむ。

## 検証

- 一振りを0.2倍速で8コマ撮り、横薙ぎと振り下ろしが弧を描き、腰が先に動き、振り抜いた後に胴が回り続けることを確かめた。
- 0.2の試験をすべて再実行し、すべて通った（完璧に遊ぶと84秒で勝利、危険な技の回避、誘い、隙、退き、負けとやり直し、一閃の画）。

## 限界（正直な評価）

手続き的に作る動きで、0.2より大きく良くなったが、SEKIROのような本当に格好いい剣戟には届かない。本番では、人体のモデルとアニメーション（モーションキャプチャか、アニメーターの手付け）が必要になる。手触りが合格したら、その作り方を決める。
