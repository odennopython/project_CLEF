# 48. 画の質を上げる作り方：参照動画・コンセプト画・生成3Dの流れ（提案、2026-11-05）

## きっかけ

オーナーの指摘：「ゲームクオリティは現状ではかなり低い」。参考として、Twitter（X）で見つけた、AIを使って短期間で完成度の高いゲームを作った人の工程が共有された（原文はオーナーが貼ったもの。「24時間」「使用ツールの名前と版」などの主張は、こちらでは確かめられない）。

共有された工程（要約）：
1. 動画生成モデルで**参照動画**を作る（見た目・世界・人物のお手本）。
2. 動画のスクショから、世界をBlenderで組み直し、Three.jsに置く。
3. 人物のスクショから、画像生成で**4方向の側面図**を作り、画像から3Dを作るサービスで**3Dモデル**にする。布の物理や動きは、Claude Codeで足す。
4. 試遊して、動くことを確かめてから先へ進む。
5. 既存の絵柄に合わせ、**面ごとのコンセプト画**を画像生成で作る（一面に最大8枚）。
6. コンセプト画を、一つずつ3Dの面にする。遊ぶ→不具合を挙げる→エージェントに直させる、を繰り返す。

## 率直な診断：なぜ今の画が低いのか

| 今 | 参考の工程 |
|---|---|
| 人物も、建物も、木も、**コードで組んだ箱・球・円錐**と、コードで描いたテクスチャ。作り手（私）の絵の腕が、そのまま画の限界 | **画像生成と3D生成が、絵そのものを作る**。コードは、それを置いて動かす |
| 先に「こう見えるべき」という**基準の絵**が無いまま、部品から積み上げた。出来を測る物差しが無かった | 最初に参照動画・コンセプト画があり、全部をそれに寄せる |
| 戦いの気持ちよさ（読み・返し・仕組み）は強い | 同様に、動きと当たりの手応えはコードで作る |

つまり、**戦いの設計は今のまま活かし、見た目（人物・景色・小物）を、生成した画と3Dに置き換える**のが筋。

## できること／できないこと（この環境）

- **できない**：動画・画像・3Dの生成（そのための道具をこの環境は持たない）。
- **できる**：
  - 生成に渡す**指示文と仕様**を書く（絵柄の固定、4方向図、面ごとのコンセプト画の枠、ポリゴン数の上限、名前の付け方）。
  - **GLB（3Dの形式）を読み込んで、人物・小物・景色として置く**仕組み。人物は、今の動き（姿勢の目標から骨を動かす仕組み）を、渡された骨にそのまま当てる（骨の名前の対応表）。
  - 重さの管理：生成された3Dは重い（数十万ポリゴン）ことが多い。間引き・テクスチャの圧縮・実機（iPhone）の予算内への調整。
  - 組み込んだ結果を、縦長の画面で撮って、基準の絵と見比べ、直す。
  - 複数のエージェントを並べて、面ごとに組む・確かめる（オーナーが「ワークフローで並列に」と明示した場合に、その方式を使う）。

## 提案：まず一枚（縦に一本通す）

全部を作り替える前に、**一つの場面と一人の人物**で、工程が通るかを確かめる。

1. **場面**：一合目の最初の開け（夜の雪の森、御神木）。
2. **人物**：主人公。
3. オーナーが作る：参照画像（または短い動画）と、主人公の4方向図。私は指示文を用意する。
4. 私が：3Dの人物と小物を組み込み、今の動き・戦いに載せ、撮って比べる。
5. 良ければ、他の合目・勢力・世界へ広げる。駄目なら、どこが駄目かを見て、工程を直す。

## オーナーに用意してほしいもの（第一段）

- 主人公：正面・背面・左右の4方向図（背景は単色、同じ光、同じ縮尺）。刀と鞘と編み笠付き。
- 3D化したGLB：骨入り（人型）、1体で30万ポリゴン以内（こちらで間引く）、テクスチャ付き。
- 一合目の最初の開けの、コンセプト画3〜5枚（遠景、地面、御神木、灯籠、焚き火）。縦長の画面（iPhone縦）で、主人公の後ろ姿から見た構図。

## 技術メモ

- 読み込み：Three.js r128 に、同じ版の GLTFLoader を足す。
- 公開：今は単独のHTMLに全てを埋め込んでいる（約8MB）。3Dを入れると巨大になるので、`play/` に資産ファイル（GLB・画像）を別に置いて読み込む形に変える（GitHub Pages は静的ファイルを配れる）。
- 人物の動き：今の人物は、独自の骨（腰・胸・首・腕・脚など18本）を、姿勢の目標から動かす作り。渡された人型の骨に、この対応表を作れば、動きの設計はそのまま使える。布（袴・襟巻・帯）は、骨に付けて物理で揺らす。
- 実機の重さ：人物と背景で一コマに描く三角形は、今約50万〜77万。生成された3Dは、ここへ足されるので、数を決めて間引く。

3. 画像・3Dの生成は、オーナーが行う（私は指示文・仕様・組み込み・確認を担当）、でよいか。

## 実施記録（試作 7.0、2026-11-05）

オーナーの回答：「用意する必要はない。方向性と世界観は今のままで、見た目のクオリティを圧倒的に上げてほしい。3Dもあなたに任せる」。

この環境では、画像・動画・3Dの**生成モデルは使えない**。そこで、できる範囲（描画・材質・光・色）を先に底上げした。**形（人物・建物の造形）の作り込みは、まだ**。

やったこと：
1. **世界の材質に、細かな質感を足した**（雪、石、木、畳、岩、木の葉などの全て）：表面の濃淡の揺らぎ、微細な凹凸（光の当たり方が変わる）、雪のきらめき（見る角度で光る粒）。物の座標で作るので、世界をずらしても模様は泳がない。
2. **人物の布の凹凸を強く**した：糸の目を数倍に、袴や着物に、ゆるいしわを足した。
3. **後処理を作り直した**：フィルム調の階調（明暗の締まり、白飛びの抑え）、世界ごとの色の調整（影は冷たく・明るい所は暖かく。雪山は青、寺は夕映え、城の広間は灯りの暖色、水は青緑、砂は金）、**奥行きのぼけ**（画面の上＝遠景を、写真のようにぼかす）、月の光の筋、細かな粒（階調の段を消す）。
4. 以前の試作 6.x の動き・技には触れていない。

率直な限界：
- 人物・建物・木の**形そのもの**は、箱と球を元にした造形のまま。ここが、参考にした作品との一番の差。形を変えるには、造形の作り込み（髪、顔、衣の重なり、鎧の細部、建物の部材）が要る。次の段階で取り組む。
- 重さは、実機で確かめていない。後処理に五つの小さな描画（四分の一の大きさ）、材質の細部に数回の雑音計算を足したので、遅ければ軽くする。

### 試作 7.1（2026-11-05 夜）：動きとステージの底上げ（第二弾）
オーナーの指示：「今夜できる限り限界まで、動きとステージのクオリティを上げる」。
- **動き**
  - 人物の姿勢のなじませを、**二次の臨界減衰**（スムースダンプ）にした。目標の姿勢が急に変わっても、動きの速さが途切れず連続して変わる。始まりと終わりが滑らかになり、「ぬるぬる」感が出る。
  - **カメラの緊張**：相手の技が刃に近づくほど、わずかに寄り、視野が締まる（息を詰めるように）。技が終わるとゆっくり戻る。呼吸のような、ごく小さな揺れも足した。
- **ステージ**
  - **灯りの足もとの光だまり**：灯籠・行灯の周りの地面に、暖かい光が落ちる。炎のゆらぎも、大きな揺れに細かな揺れが重なるようにした。
  - **オーロラ**：空の遠くに、ゆっくり波打つ光のカーテン（雪山・水月・風紋・雲上。寺・城・屋内には出さない）。
  - **足もとの薄い霧**：ゆっくり流れる濃淡の層。
  - **木のそよぎ**：杉・竹・楓・桜が、枝先ほど大きく、一本ごとに位相をずらして揺れる（吹雪の面ほど風が強い、とはまだ連動していない）。
  - **星のまたたき**。
- 率直な限界：実機での重さと、動きの手触りは未確認。人物・建物の形そのものは、まだ作り替えていない。

### 試作 7.2：滑らかさを守る（自動で軽くする）
- コマの間隔が約25ms（約40コマ/秒）より長く続くと、**段階的に重い表現を減らす**：一段目＝奥行きのぼけと月の光の筋を止める、二段目＝描く細かさを下げる（1倍）、三段目＝さらに下げる（0.85倍、影は三コマに一度）。滑らかさは、見た目より先に守る。
- 試験用に、URL に `?hq` を付けると、自動では軽くしない。
- 実機での効き具合は未確認。しきい値（25ms、150コマ）は仮の値。
